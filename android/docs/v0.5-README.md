# IPMsg for Android

A native Kotlin / Jetpack Compose companion for Windows IP Messenger. Android 10 or later. No accounts or cloud service. This is a **test build**; see TESTING.md for verified checks and remaining device validation.

## v0.5.0

Install IPMsg-v0.5.0.apk over the existing Lantern/IPMsg app; keep your history, settings and keys. The package and signing key are unchanged.

- Received and sent messages have rounded, outlined bubbles, larger readable text and clickable web links.
- A new device needs confirmation before opening its first conversation or sending to it. Discovery and incoming notifications still work automatically; this is an outgoing connection approval, not a new authentication protocol. Removing a device revokes this approval.
- Settings shows **My IP** near the top.
- Accepted downloads go to **Downloads/IPMsg** by default. Settings → Storage → Change folder selects another writable folder, or Use default restores Downloads/IPMsg. Each file still needs acceptance. Duplicate names create separate files. Partial default downloads remain pending and are removed on failure/cancellation. Moving a saved file may invalidate its chat link. If a selected folder's permission is revoked, choose it again; the app does not silently save elsewhere.
- Chat → Attach → **Live camera** asks the owner to share, then requests Android camera permission. The phone must keep its live-camera screen open. Send viewing link sends a temporary link to the selected peer; open it in that device's browser. The viewer needs no Windows add-on. The link accepts only the selected source IP and expires after ten minutes. Returning to chat, locking the phone, or leaving the app ends the session. A fresh session needs fresh approval and a new link.
- The live viewer shows lightweight JPEG previews (about three updates per second, device dependent), without audio. **Request recording** only opens a permission dialog on the owner's phone. Nothing records until the owner chooses Record. Owner or viewer can stop an approved recording. Silent MP4 recordings are saved in Movies/IPMsg, with a separate Share saved recording action. Recordings are capped at ten minutes / 512 MiB and are finalized when the owner leaves. A failed recording is discarded where possible.
- Live camera uses **unencrypted local HTTP**, with a random session token, exact source-IP restriction, same-origin recording requests, bounded clients/headers and foreground-only lifetime. This is disclosed before sharing. Use only a trusted LAN. Browser history may retain a now-expired link. Owner approval controls this app's recorder; it cannot prevent a viewer from independently taking screenshots or recording their own screen. No microphone or all-files permission is requested.
- Live camera needs Android Camera2 preview/recording support. If a phone cannot combine the outputs, the camera screen closes with an error; the existing Take photo / Record video actions remain available. Do not expose the live-view port to the internet. Download port 2425 and Windows Firewall setup are unchanged.

Implementation references: [Android Camera2 simultaneous streams](https://developer.android.com/media/camera/camera2/multiple-camera-streams-simultaneously), [Android shared media storage](https://developer.android.com/training/data-storage/shared/media).

## v0.4.0 (previous release)

The launcher name is now **IPMsg**. Install this APK over Lantern; do not uninstall. The package ID, signing key, history and peer identity remain compatible with the existing app. This is an independent, unofficial Android client.

- Cleaner device and chat screens; detailed encryption information is under Settings → Security details. Plaintext sharing still requires consent unless disabled altogether by secure-only mode.
- Foreground pop-up banners and background high-importance notifications for online/device connections, received chats/files and saved downloads. Enable Android notifications; heads-up display also depends on Android's channel and Do Not Disturb settings. Settings controls alerts, device announcements and message previews.
- Saved file cards belong to their original chat. Save, Open and Folder actions are available there; Files lists all retained transfers and opens their source chat. Image thumbnails are shown when the provider supports them. Incoming save destinations retain URI grants when the provider permits. Saved links and file records survive process restarts; unfinished session offers become Expired. File history starts with this version; earlier versions did not store file links.
- Chat → + Attach → Browse files / Photos & videos / Take photo / Record video. The camera opens Android's capture application with its preview and capture controls; no live stream or remote camera control is exposed. Successful photos go to Pictures/IPMsg and recordings to Movies/IPMsg. Captures are offered to the originally selected recipient only after sharing confirmation; cancelled captures are deleted. The app does not request broad camera, microphone, or all-files access.
- Settings → Browse storage uses Android's local file browser and shows available internal storage. Selecting a file there does not share it. Chat attachment selection is a separate action. Folder opens the containing folder when the document provider supports it; otherwise Android's file browser is used. Android's private/protected app storage remains inaccessible.
- Add the IPMsg Home-screen widget from Settings or your launcher's Widgets menu. It opens IPMsg and starts/stops listening. Opening the app once is required to grant notification permission. A launcher supporting pinned widgets may show an Add dialog.
- Remove a device from Nearby to stop its current file offers, hide it, and block packets from that IP address. It stays blocked until restored in Settings or deliberately added by IP again. Chats and saved files remain. Blocking follows an IP address, so reassigned DHCP addresses may also require restoring.
- Optional secure-only messages and secure-only file uploads, bounded per-address UDP processing, a device-count limit, retained key pinning, and offer revocation when clearing history. These controls do not turn classic IPMsg discovery into an authenticated directory or add an integrity tag to its legacy file body.
- Transfers use reusable 128 KiB input/output buffers, avoid per-chunk byte-array copies, use a larger download receive buffer, and persist file state only when it changes. These reduce allocation and database work; no fixed Wi-Fi speed increase is promised. The v0.3 completion-handshake fix remains in place.

Camera API reference: https://developer.android.com/reference/androidx/activity/result/contract/ActivityResultContracts

Stop listening in IPMsg Mobile or any other client before enabling IPMsg on the same phone; both need port 2425. Saved external files are not deleted when chat history is cleared. Active file offers are stopped before clearing their chat records. The two secure-only switches may prevent old/incompatible peers from exchanging plaintext; leave them off for the original explicit-consent behavior.

## v0.3.0 update

Fixes completed downloads failing with `Read timed out`: classic IPMsg files are complete after the advertised byte count; Windows then waits for the receiver to close the connection. Lantern now flushes the destination and closes its socket without waiting for Windows EOF. This applies equally to APKs, ZIPs, photos and other regular files, encrypted or plaintext. Truncated connections still fail and remove the partial destination where the provider permits; the error now reports received/expected bytes. Retry starts again from zero. A changed or interrupted source may require a new offer from Windows.

Features inspired by the supplied IPMsg Mobile ZIP: search nearby devices by name/computer/IP, persistent unread badges, clearing one conversation with confirmation, incoming/outgoing transfer filters, percentage progress and network diagnostics with removable manual addresses. Android Back returns from a conversation to the conversation list. Notification routing now uses the actual offer type rather than comparing message text.

Install over v0.2.0 without uninstalling to preserve history, identity and keys. The database upgrades in place; old messages begin as read, and new incoming messages remain unread until their conversation is visible while the app is in the foreground. Counts cover the latest 2,000 displayed messages. Clearing a conversation retains content-free replay protection.

Stop listening in other Android IPMsg clients (including IPMsg Mobile) before enabling Lantern: both use UDP/TCP 2425 on the same phone. A port conflict is shown as a listening error. The original IP Messenger logo is retained.

## Install and connect

1. Copy `LanternLAN-debug.apk` to your Android phone. Open it and allow installation from that file manager when Android asks. This APK uses a development signing key.
2. Start Windows IP Messenger. The implementation targets the classic protocol used by Windows 5.9.1. Official Windows download: <https://ipmsg.org/>.
3. Connect the phone to Wi-Fi and Windows to the same router (Ethernet is fine). Avoid guest Wi-Fi or access-point/client isolation.
4. Allow **IP Messenger** through Windows Defender Firewall on your trusted **Private** network. Both inbound UDP 2425 (discovery/messages) and TCP 2425 (files) must be permitted. Use Windows Security → Firewall & network protection → Allow an app through firewall. If application rules do not suffice, add separate inbound UDP/TCP port-2425 rules for the Private profile, scoped to Local subnet. No router port forwarding is needed.
5. Open Lantern → Nearby → **Start listening**. Allow notifications so incoming messages are visible. Wait a few seconds, then Refresh. You can also add the PC's IPv4 address (find it with `ipconfig` on Windows).
6. Tap the PC to chat. Encryption becomes available after key exchange. If it is unavailable, sending requires explicit plaintext confirmation.
7. Use **Attach file / photo** to choose one file. Keep listening enabled until the receiver downloads it. Offers expire after one hour or when listening stops.
8. Incoming files appear in **Transfers**. Choose **Accept & save** and a destination in Android's file picker. The picker handles existing filenames; choose a new name to avoid replacing a file. Cancellation/failure attempts to delete the partial document; some providers may leave an empty or partial file that you must remove manually.

## Background receiving

Listening runs as a foreground connected-device service with a persistent notification. Use its **Stop** action or Nearby → Stop listening when finished. It does not restart at boot or after Android kills the process. Some phone manufacturers restrict background Wi-Fi; if reception stops, reopen Lantern and check battery restrictions for this app. Notifications can be disabled independently of listening by Android.

## Security and privacy

- Message encryption follows IPMsg RSA-2048 / AES-256-CBC, with SHA-256 or SHA-1 RSA signatures when negotiated. Incoming signed messages are rejected if their signature cannot be verified.
- RSA keys live in Android Keystore. Peer keys use trust on first use, pinned by address and IPMsg user ID. Compare fingerprints in Settings through another channel. A changed pinned key is rejected; reset trust only after verifying the peer. This is not a centrally authenticated identity system; a peer's changing user ID or IP address establishes a new first-use identity.
- Encrypted downloads use IPMsg AES-CTR when the peer advertises support. File bytes in this protocol are not authenticated. Plaintext file downloads need confirmation. Before offering any file, Lantern warns that the receiver may request plaintext. Sending a file grants that IP address temporary download access while the offer remains active.
- History stays in an app-private SQLite database. It is not separately encrypted at rest; Android device encryption protects it according to the device settings. Android backup is disabled. Clear history in Settings removes all stored messages. The UI shows the latest 2,000.
- No analytics, advertising SDK, cloud account, or automatic public-network connection. Use trusted local networks.
- This version supports IPv4, UTF-8 peers, individual files and photos. It does not support folders, inline clipboard-image pseudo-files, internet messaging, voice/video, IPv6, or Member Master. Acknowledged means delivered to the peer application, not read by a person.
- UDP delivery retries use the same packet number. If acknowledgments are lost, the UI reports **delivery unknown**, not a definitive failure. Duplicate suppression survives restarts using a bounded ledger of roughly 8,192 receipt IDs. Message bodies and receipt IDs commit together before acknowledgment. Content-free receipt metadata remains after clearing history.
- File offers and transfer activity are session-only. Restarting listening invalidates them; ask the sender to offer again. Transfers do not resume after interruption.

## Conversations and files

Use Search history or Search this conversation to filter messages. Copy selects a message for the Android clipboard; long press also allows text selection. The app follows the system dark theme. A different IPMsg user appearing at the same address is treated as a different conversation.

Drafts and pending file-picker routing survive Activity recreation. A confirmation dialog is dismissed on recreation to avoid silently approving a send. NOLOG message bodies remain in volatile memory only. Saved files have an Open action for compatible installed apps. Retry starts a failed download from zero and asks you to choose a new destination.

## Build

Requires JDK 17, Android SDK platform 35, Internet access for Gradle dependencies, and SDK licenses accepted. Set `ANDROID_HOME` to the SDK directory or create an untracked `local.properties` containing `sdk.dir=...`.

Windows PowerShell:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\sdk"
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

macOS/Linux: `sh ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`.

The build uses Gradle 8.11.1, Android Gradle Plugin 8.9.1, Kotlin 2.1.20 and Compose BOM 2025.04.01. There are no bundled Windows executables and no release keystore in the source archive. Create your own production signing key for distribution; an APK signed with a different key cannot update an installed test APK without uninstalling it.
