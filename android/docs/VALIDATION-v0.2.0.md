# Validation report

Test date: November 4, 2026. Lantern LAN 0.2.0 is a development test build.

## Verified

- Android debug APK compiled with JDK 17, Android SDK 35, Gradle 8.11.1, AGP 8.9.1 and Kotlin 2.1.20.
- 20 JVM tests pass. Seven new tests cover durable packet reservation, clock rollback, persistence failures, numeric bounds, identity matching, request termination and handshake deadlines (including trickled input). The original 13 cover: UTF-8 (including Arabic and emoji), message colons and NUL-separated attachment metadata, escaped filenames, empty files and >4 GB metadata, malformed packet rejection, CP932 decoding, safe destination names, bounded duplicate suppression, packet-number IVs, RSA/AES hex and Base64 modes, signed-message validation, invalid/unknown signature rejection, and framed regular-file header byte lengths.
- Baseline Windows interoperability was verified during v0.1 development; its real-packet regression fixture passes again in v0.2. The official Windows 5.9.1 installer and extracted executable had valid FastCopy Lab Authenticode signatures. A separate instance bound to loopback port 3425 was used without installing it or changing Windows Firewall rules.
- Real Windows 5.9.1 discovery and public-key exchange succeeded with the probe peer.
- A Windows-generated RSA-2048 / AES-256 message was decrypted and its signature verified. The captured wire packet is included as a JVM regression fixture and is decrypted by **the app's Kotlin crypto implementation**. The fixture's private key is an ephemeral test peer, not a production or user key.
- In the reverse direction, ciphertext and a signature generated by **the app's Kotlin crypto implementation** were sent to Windows 5.9.1. Windows acknowledged the message and its receiver output recorded `RSA2/Signed+`, with the expected Unicode text.
- The IPMsg key-fingerprint calculation was checked against the actual Windows public key and announced user fingerprint.
- APK signing verification passed (APK signature scheme v2). The manifest declares minimum API 29 (Android 10) and target API 35.
- Android lint completed successfully with zero errors; advisory warnings remain for dependency updates, target API, and style/platform suggestions.
- Android 15 v0.2 regression checks passed: 3 engine/database integration tests and 1 UI test. The engine checks cover signatures, sender-identity rejection, unsigned-downgrade rejection, retries, encrypted/plaintext files, zero-byte and 256 KB data, framed requests, cancellation, truncated streams, offer expiry, migration and durable replay. The UI test verifies drafts through Activity recreation and navigating away/back, plus history search. Tests were rerun selectively after correcting fixture setup and accessibility selectors; the final UI test passed in 30.44 seconds.
- Baseline v0.1 Android 15 UI smoke checks passed for Nearby, Chats, Transfers and Settings. Starting listening showed Online and Android reported the connected-device service as foreground with an ongoing notification. Stopping listening returned to Offline. No application crash was recorded during these checks. `LanternLAN-preview.png` shows the initial screen.

The v0.2 UI smoke check also passed across all four tabs, listening start/stop and the actual foreground service. Light and dark screenshots were inspected; the dark navigation-bar contrast issue found during inspection was corrected and verified on the final APK. The final color-only adjustment was rebuilt and visually checked; the engine/database/UI regression passes above precede that adjustment.

These loopback checks verify classic protocol/encryption behavior, not real phone Wi-Fi or end-to-end Windows file transfer.

## Runtime test suite

The Android instrumentation suite in `app/src/androidTest/` exercises the actual networking engine and Android Keystore, using local UDP/TCP peers:

- Discovery and key exchange, verified encrypted Unicode messages, duplicate acknowledgment without duplicate history, a deliberately dropped acknowledgment and same-packet retry.
- Encrypted and plaintext uploads/downloads, empty and 256 KB files, and regular files using the framed transfer command.
- Truncated-transfer failure, active download cancellation, retry from byte zero, offer expiry, clear history, and stopping listening.
- Spoofed sender identities, unsigned downgrades from signing-capable peers, mismatched-recipient send rejection, and visible-but-unlogged message bodies.
- Database migration from v1, persistent replay protection after database reopen, and draft restoration/history search through Activity recreation.

Run on an attached Android device/emulator:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

Alternatively, build both APKs, stop Gradle to free memory, install the app APK and `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`, then run:

```powershell
adb shell am instrument -w -r app.lantern.lan.test/androidx.test.runner.AndroidJUnitRunner
```

The available Android 17 preview emulator initially suffered widespread system-app startup ANRs under host memory pressure. Those interrupted runs are **not counted as passing runtime tests**.
The suite subsequently passed on a stable Android 15 AOSP emulator, with Gradle stopped to reduce host memory pressure.

## Physical-device acceptance still required

No physical Android phone was connected during development. Before treating this as production-ready, complete these checks with Windows 5.9.1:

1. On the same router, verify automatic discovery both ways, then manual-IP discovery. Repeat with Windows on Ethernet and the phone on Wi-Fi.
2. Exchange English, Arabic, emoji, multiline messages, and messages containing colons. Verify delivered status, signature verification, and a plaintext confirmation against a legacy peer. Confirm no automatic plaintext downgrade.
3. Send files and photos in both directions, including 0 bytes, 256 KB, and a multi-GB file. Compare SHA-256 hashes. Exercise Windows encrypted-transfer settings both on and off, and filenames with spaces/Unicode.
4. Accept and decline offers. Save twice with the same filename and confirm the provider's replacement/new-name behavior. Cancel mid-transfer, disconnect Wi-Fi, stop the sender, and stop listening; verify failures are shown and remove any provider-retained partial documents.
5. Turn off the screen, leave Lantern in the background for at least 30 minutes, and verify message notifications. Test notification permission denied, battery restrictions, Wi-Fi reconnection, app force-stop and relaunch.
6. Verify changed pinned keys are rejected, inspect fingerprints through another channel, and test the explicit reset-trust flow.
7. Clear history, relaunch, and confirm it stays cleared. Check that saved files remain where chosen and that old offers cannot be downloaded after stopping listening.

Transfer performance, manufacturer battery policies, very large real transfers, Android 10 device behavior, and routed/guest-network behavior are not yet certified.
