# IPMsg 0.6.0 release-candidate review

The update prioritizes trust, recovery and small daily shortcuts while preserving four tabs and the existing Windows wire protocol.

## Changes

- Central outbound authorization covers messages, file offers, camera links, direct notification replies and reviewed queued sends. Secure approvals are fingerprint-scoped; legacy approvals remain address-scoped. Earlier IP approvals are not silently promoted to verified identities. Device-specific revocation/reset replaces the exposed global trust reset.
- Camera HTTP was removed. TLS 1.2/1.3 uses an Android Keystore P-256 ECDSA key and an IP-specific leaf certificate. A one-use fragment token becomes a secure session cookie. Browser certificate verification remains explicit; there is no insecure fallback.
- Typed transfer phases drive controls, retryable offers survive interrupted attempts, and partial destinations are tracked. Destination publication follows advertised-byte completion and storage checks. Active transfers use a bounded wake lock. This is restart recovery, not resumable transfer.
- Database-backed search and older-message pages replace searching only the last 2,000 loaded messages. File links remain in their source conversation.
- Android Share, up to 30 files, batch cancellation, favorites, local nicknames, deliberate clipboard sharing, message actions, notification reply/read actions and a persistent review-only outbox were added.
- Release shrinking and external private-key signing replace debug distribution. Signing lineage is verified; physical upgrade acceptance remains pending unless separately reported in TESTING.md.

## Remaining limits

This is a release candidate, not a declaration of daily-use readiness. Physical phone/Windows 5.9.1 interoperability, real Wi-Fi reconnection and screen-off behavior, OEM camera/document providers, sustained transfers, battery/memory/throughput comparisons and accessibility acceptance still need device testing. Headless browser pinning tests, if passed, do not establish the user's manual certificate-exception workflow.

Classic IPMsg encrypted files lack authenticated contents. File offers are memory/session-bound; process death needs renewed offers. Retry restarts from zero. Provider cleanup is best effort, and unknown provider lengths cannot always be independently inspected. Source URIs must stay readable; a changed source needs a fresh explicit offer. Browser recording cannot prevent independent screen capture. No cloud, broad CA installation, remote storage access, audio or incompatible pairing commands were added.
