# IPMsg 0.7.5 scope

Simplify chat controls, replace the camera's legacy button layout with a Compose preview and compact controls, enable inline text chat without leaving the foreground camera, and add owner-controlled microphone sharing to the same HTTPS viewer. No account, cloud service or Windows companion is added.

The microphone defaults off for every session, including when Android permission was previously granted. Enabling requires explicit owner consent to hearing and recording plus the runtime microphone permission. Browser controls cannot enable capture. Phone mute closes audio sockets and clears bounded buffers; browser mute/session termination clears scheduled playback. Capture stops on pause/background/lock, expiry, revocation and LAN identity change. No background camera/microphone service is introduced.

Audio uses the existing TLS certificate, single-use authentication, Secure/HttpOnly/SameSite cookie, origin checks, allowed receiver IP and session lifetime. A bounded PCM queue drops stale audio rather than accumulating delay. Only one audio stream is accepted at once. The browser creates receiver-only WebM recordings with a silent-until-enabled audio track, limited by time and approximate memory use. Classic IPMsg messages/files and the 0.7.4 hotspot routing policy are preserved.

Inline chat uses the existing source conversation, history and outbound authorization. Plaintext requires deliberate consent; approved secure identities do not downgrade. Unsent drafts are retained and conflicting drafts are not overwritten. Search/details/secondary actions are tucked into the conversation menu; file actions remain accessible in main chat. Physical layout, recording playability, microphone behavior and sound/video synchronization remain acceptance items.
