# IPMsg 0.5.0 validation

November 5, 2026. Development test APK; Android 10+. Package app.lantern.lan, version code 5.

## Build and signing

The final application assembled successfully, all 30 JVM unit tests passed and Android lint reported zero errors (47 advisory warnings). Signature verification passed and the signing certificate matches previous Lantern/IPMsg APKs, permitting an in-place update. The Android instrumentation test APK was rebuilt after test-only locator corrections; production sources remained unchanged.

Unit coverage: 13 protocol/crypto, 7 network safety, 5 transfer completion/cancellation/streaming, 2 packet-rate budgets and 3 live camera HTTP server cases. The new server tests verify token and exact-peer restrictions, rejected cross-origin recording requests, expiry and revocation on close. A recording request invokes only the owner-request callback.

## Android runtime: 15 cases passed

- Eight engine/database cases passed on the final APK in 20.209 seconds. They exercise actual UDP/TCP, signed encryption, ACK/retries, duplicate suppression, ordinary/encrypted/empty/truncated/cancelled transfers, history migration, replay persistence, plaintext restrictions, removed devices, durable file links and cancelled capture cleanup.
- Five UI cases passed: first-device confirmation and cancellation; separate live-camera consent; draft restoration and chat/history search; unread/read state and clearing a conversation; saved-photo cards with Open/Folder and attachment actions; notification switches both visually and persistently toggling. The chat preview is a screenshot of synthetic test messages, not a design mockup.
- Two camera/storage cases passed in 57.204 seconds. The camera test opens Android Camera2, verifies distinct JPEG frame colors, submits a viewer recording request, confirms no recorder exists until the owner approves, declines the first request, approves another, records and stops, verifies a playable MP4 with MediaMetadataRetriever, then opens the main activity and verifies the old link is revoked. Its test recording is deleted afterward. The storage case verifies default Download/IPMsg pending rows, publication after writing, separate destinations for duplicate filenames, and intact file bytes.

Startup validation caught network initialization on the main thread; it now runs on a worker. A heavily memory-constrained emulator run reset an HTTP request, so final runtime checks were run after build daemons exited. Native dialog tests match Android's uppercase button presentation; draft tests detect a chat by its attachment control, rather than assuming its input is empty. No production behavior was weakened to satisfy those tests.

## Practical limits and physical-phone acceptance

This is an Android 15 emulator validation with a synthetic camera. No physical phone was connected. Verify real camera framing/orientation, OEM camera and document-provider behavior, Windows browser access over actual Wi-Fi, locking/background transitions, long recording stability, notifications under battery restrictions, and large file transfers on your phone. The custom-folder picker retains Android URI grants, but each OEM/cloud document provider still needs device acceptance. No real Wi-Fi throughput claim is made.

The classic IPMsg protocol and v0.3 advertised-size download completion fix remain in place; this update did not repeat the previous Windows interoperability checks. Older validation reports are in docs/.

Live preview is low-rate JPEG over unencrypted local HTTP without audio. The owner sees this warning before sharing. A token, exact peer-IP restriction and ten-minute deadline limit access; leaving the camera screen closes its sockets. The owner approval controls IPMsg's recorder, not an independent viewer's screen capture. Use only a trusted LAN. Recordings save to Movies/IPMsg and need a separate sharing action. Forced process termination may leave pending media for system expiry. Failed downloads are deleted where the storage provider permits; saved links can fail if the user moves or deletes the file or revokes its grant. Classic encrypted file bodies still lack an authentication tag.

## Install

Install over Lantern/IPMsg without uninstalling to retain history, keys and settings. Stop listening in the separate IPMsg Mobile app first. Accept incoming files in their chat; they save to Downloads/IPMsg by default. Change or reset the folder under Settings → Storage. My IP appears near the top of Settings. For live camera, use Chat → Attach → Live camera, approve on the phone, send the viewing link, and keep that screen open. The viewer's Request recording action must then be approved separately on the phone.
