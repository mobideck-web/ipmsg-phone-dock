# IPMsg 0.7.0 release-candidate review

This update prioritizes camera choice, useful transfer recovery and deliberate storage cleanup. It keeps local operation, four tabs, Windows IPMsg compatibility and the existing application/signing identity.

## Changes

The visual system now uses green and neutral surfaces consistently in light and dark mode, with line navigation icons. Messages retain separate incoming/outgoing boxes. Camera controls use compact rows and the browser viewer fits the screen.

Smooth and Clear provide bounded resolution, JPEG quality and encoding cadence; supported camera output combinations are selected conservatively. Changing quality needs confirmation and ends the existing session. Owner approval to share, TLS verification and lock/background revocation remain. The sharing confirmation grants receiver recording and photo capture. Dedicated sender notifications and visible status accompany receiver actions; camera notifications must remain enabled. Authenticated JPEG capture is rate limited. Completed MP4 downloads stream in bounded chunks over the same HTTPS session without exposing arbitrary files. Quality cannot change while a recorder is active.

Transfer recovery distinguishes typed timeout, truncated connection, permission/storage and changed-source failures. Restart is explicit and begins at byte zero. Expired transfers are not revived. Retained outgoing offers remain available only under the existing permission/expiry; non-retryable source/access failures discard them. Failure metadata is restored from the database without reviving active work. Partial deletion no longer discards tracking when provider deletion fails.

Storage cleanup lists app-owned Downloads and tracked custom destinations, plus unlinked outbox staging files older than an hour. The removal boundary rechecks active/queued references. Linked copies are retained. Confirmed download removal clears stale file links and marks the attachment removed while leaving messages intact. Selected failures remain visible instead of claiming they were deleted. Private keys, identity, preferences and history databases are never cleanup targets.

## Limits

No cross-process transfer resume, automatic retry, background camera, remote phone-storage browsing or cloud service. Classic encrypted file bodies remain unauthenticated. Physical S25 Ultra and OnePlus Ace 5 orientation/latency, sustained real-Wi-Fi Windows 5.9.1 transfers, low storage/revoked-provider behavior and battery/throughput acceptance remain pending. No measured speed improvement is claimed from configuration limits.
