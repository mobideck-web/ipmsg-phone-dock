# IPMsg 0.7.4 scope

Correct offline hotspot discovery and local route selection, add sender-controlled camera flashlight, clarify strict encryption compatibility and refine the existing four-tab UI. No accounts, cloud services or new Windows companion.

The previous discovery loop sent 255.255.255.255 first and aborted all destinations on one exception. The new loop attempts directed local broadcasts and manual addresses independently. Source-bound UDP sockets retain port 2425 and receive replies; network-handle changes replace stale sockets even if the IP is unchanged. TCP downloads bind the matching LAN. Internet validation and cellular availability are not prerequisites.

Hotspots not exposed as an Android Network use their local interface/source address. This is subject to OEM routing/VPN policy; no physical data-off hotspot success is claimed without testing. LAN interface polling runs only while listening. Strict security settings and defaults are preserved. Rejected plaintext file requests are visible and do not change the original offer expiry or sharing permission.

Flashlight controls only the selected camera on the owner's phone. Camera shutdown requests torch off and closes the camera. Camera LAN identity changes close the viewer session; unrelated cellular-default changes do not. Hardware behavior, notification visibility and UI acceptance still need physical-device checks.
