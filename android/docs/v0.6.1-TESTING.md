# IPMsg 0.6.1 RC1 validation

November 5, 2026. Android 10+, app.lantern.lan, version code 7. History schema remains 6. Same private release key and original signing lineage as 0.6.0.

## Build and automated checks

The final debug/test and optimized release builds passed. Release code and resources are shrunk. Android lint: zero errors, 67 warnings, including deprecated system-bar APIs and hardcoded strings. These warnings remain; this is not a claim of a warning-free build.

35 JVM tests passed: protocol/crypto 13, network safety 7, file transfer 5, packet rate limits 2, HTTPS server 5 and camera conversion/rotation 3. New checks cover padded/interleaved planes, direct buffers and their positions, reusable-buffer freshness, all quarter-turn rotations, authenticated multipart streaming, fresh frame delivery and expiry.

21 substantive Android runtime cases passed across staged emulator runs: eight engine/database, six product/policy, five UI and two camera/storage. A 22nd reported case returns on debug builds and is not counted as release-signing evidence. Coverage includes UDP/TCP, signatures, ACK/retries, duplicate packets, file errors, migrations, refreshed names and offline nicknames without implicit approval, review-only queued items, old-history search, chat controls and storage publication. A naming-test identity was changed to be unique after a repeated snapshot run encountered its own previously approved fixture.

The final camera/storage run passed both cases in 75.899 seconds: decoded real Camera2 images, fresh frames during recording, separate owner recording permission, declined recording, playable saved MP4, revocation after leaving, transactional default downloads and distinct duplicate filenames. Earlier experiments with an automatic screen-readback fallback caused stalls in the emulator renderer; that automatic fallback was removed. Normal streaming uses background bulk YUV conversion. Only unsupported combined recording outputs use the smaller compatibility preview. The final UI screenshot contains synthetic messages.

## Windows browser checks

Installed Windows Chrome and Edge each rejected the untrusted certificate with a mismatched SPKI and rendered a 480 x 640 portrait Camera2 image after trusting only the expected key. Authentication removed the token fragment from the address bar, and recording controls became available. Native browser fixtures completed successfully (Chrome 73.534 seconds; Edge 66.545 seconds). Isolated automation profiles were used; global browser certificate validation was not disabled.

The browser DevTools MJPEG incremental-byte counter returned zero despite decoding the image. It is not used as continuity or throughput evidence. Fresh-frame delivery is covered by the native recording case and HTTPS server stream tests. Sustained Windows viewing on physical Wi-Fi, actual latency, the manual certificate-comparison/site-exception workflow and browser policy behavior remain acceptance checks.

## Exact release verification

The exact signed distribution APK passed the framework-only probe after installation over the existing test app. It is non-debuggable, reports version 0.6.1/code 7, retains the original signing certificate in its rotation lineage, and preserved the existing identity and both synthetic history entries. The probe verified the certificate and endpoint address, authenticated with the temporary token, obtained a session cookie and decoded a JPEG from the authenticated multipart HTTPS stream. Signing verification passed with release certificate SHA-256 00c5f3e2275a3f8a231ca1c9a21110296f37c2a24baa627b2dedadafb0249222. This is not a substitute for a physical-phone upgrade test.

## Pending physical acceptance

Galaxy S25 Ultra and OnePlus Ace 5 were identified by the user; neither is connected. Confirm upright phone/browser previews and actual latency, real-Wi-Fi behavior against Windows IP Messenger 5.9.1, screen-off/background receiving, large APK/ZIP files, reconnection, interrupted/cancelled transfers, notification actions, low storage, revoked folder grants, process death, TalkBack and battery/memory/throughput comparisons. No phone-specific performance or file-transfer-speed improvement is claimed from emulator timing. Ten encoded frames/second is a cap, not a measured guarantee.

No HTTP fallback, cloud service, automatic outbox sending, remote storage access or audio was added. Existing certificate verification and owner permission still apply. Classic encrypted IPMsg file bodies lack authentication and interrupted downloads restart from zero. Historical reports in docs describe earlier releases and do not replace the checks above.
